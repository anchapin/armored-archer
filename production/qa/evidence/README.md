# Visual-change evidence (issue #1860)

Standard location and format for the screenshot evidence that visual-change
PRs must attach (or explicitly opt out of). This is a **report-only**
convention: nothing here is a CI gate, no workflow file is touched, and no
baseline or pixel-diff comparison is performed.

The evidence is produced with the loop that #1766 (spike) and #1779 proved on
this repo: the offline PvE gameplay demo
(`scripts/gameplay_screenshot_spike.gd`) rendered under `xvfb-run`, where the
frames are **real rendered pixels**. A headless run uses Godot's dummy
renderer, whose viewport texture cannot be read back — `scripts/screenshot_capture.gd`
substitutes a 1x1 placeholder there, so headless output is never evidence.

## 1. When evidence is required

A PR needs visual evidence when it touches any of these paths:

| Trigger path | What changed |
| --- | --- |
| `scenes/ui/**` | UI layout, node tree, theme overrides |
| `assets/**` | Sprites, sprite sheets, icons |
| `themes/**` | UI themes and theme resources |
| VFX / effects code | `scenes/effects/**`, `scripts/*effect*`, `shaders/**` |
| HUD | HUD scenes/scripts (health, ammo, boss bars, score) |

Either attach the evidence, or state explicitly in the PR body **why not**.
The exact opt-out wording is in `AGENTS.md` ("Visual-change evidence") and in
`AI_CODE_REVIEW.md`.

## 2. Where the evidence lives

```text
production/qa/evidence/<issue-or-pr-id>/
├── note.md          # the structured note (required)
├── frames/          # the captured PNG frames (required)
│   ├── 01_stage_loaded.png
│   ├── ...
├── validation.json  # machine-readable output of the frame validator
└── run.log          # raw stdout/stderr of the capture run
```

- `<issue-or-pr-id>` is the issue number of the work (or the PR number when
  the evidence is produced during review), as a single path segment.
- Frames are numbered in capture order and named `<NN>_<step>.png`, matching
  the capture points of the spike demo (`stage_loaded`, `wave_spawn`,
  `shot_fired`, `enemy_death`, `boss_spawn`).
- The committed example is `production/qa/evidence/1860/` (issue #1860).

## 3. How to produce it

```sh
./scripts/capture-visual-evidence.sh --slug 1860 --stage 1_3 \
    --title "Short title of the change" \
    --observed "What the frames show." \
    --not-assessed "Anything that was not checked."
```

The wrapper (a thin extension of the #1779 spike path):

1. resolves a Godot 4.6+ binary (`--godot`, `$GODOT_BINARY`, `godot4`, `godot`,
   `.bin/godot4`) and imports the project once if the `.godot/` cache is missing,
2. runs the offline demo under `xvfb-run` and captures the real viewport at
   the five capture points,
3. validates every frame with `scripts/validate_capture_frames.py` (PNG header
   size + distinct colours in the decoded pixels),
4. **fails loudly** (exit code 1, nothing written) when the run does not
   `PASS`, when a frame is missing, or when any frame is a placeholder
   (1x1, uniform, or unreadable),
5. writes `note.md`, `frames/`, `validation.json` and `run.log`.

Exit codes: `0` evidence written, `1` capture/placeholder failure,
`2` usage error, `3` environment error (no Godot, no `xvfb-run`, import failed).

## 4. Note format

`note.md` is generated by the wrapper and must contain these sections:

```markdown
# Visual evidence — <issue-or-pr-id>

- **Issue / PR:** #<id>
- **Command run:** `<the exact command that produced the frames>`
- **Godot version:** <e.g. 4.6.stable.official.89cea1439>
- **Platform / renderer:** Linux, `xvfb-run` (software OpenGL); NOT a GPU run
- **Stage played:** `1_3` (offline PvE, no login, no server)
- **Frames stored in:** `production/qa/evidence/<id>/frames`
- **Generated by:** `scripts/capture-visual-evidence.sh` (issue #1860) ...
- **Generated at (UTC)::** <ISO-8601 timestamp>
- **Summary line from the run:** `<SPIKE_SUMMARY JSON>`

## Frames

| Frame | Step | Size | Distinct colours | Bytes |
| --- | --- | --- | --- | --- |
| `frames/01_stage_loaded.png` | stage_loaded | 640x360 | 65 | 11292 |

## What was observed

- <one line per observation>

## What was NOT assessed

- <one line per thing that was not checked>

## How to reproduce

```sh
./scripts/capture-visual-evidence.sh --slug <id> --stage <stage>
```
```

Rules for the note:

- **Command run** — the exact command, so the run can be repeated.
- **Godot version** — the `godot --version` string of the binary that ran.
- **Per-frame checks** — the size and the distinct-colour count of every
  frame. A frame must be larger than 1x1 and must not be uniform; those are
  the placeholder signatures of the headless dummy renderer.
- **What was observed** — what the frames actually show for this change.
- **What was NOT assessed** — everything the run did *not* cover. The
  untested **Windows / real-rendering-host path** must always be named here:
  the loop is Linux/`xvfb` only, and the #1766 spike never attempted the
  Windows path (no such host is reachable from that environment).

## 5. What this convention is not

- Not a CI gate: no required check, no workflow file changes.
- Not a pixel-diff comparison: the committed frames are evidence of one run,
  not baselines that future runs are compared against.
- Not a substitute for human review: the frames show what the renderer
  produced on Linux under software OpenGL, nothing more.
