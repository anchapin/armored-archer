## Cross-Phase Integration Issues

### 1. Phase 04 Benchmarks Don't Use Phase 02 Fixtures

**Issue:** `backend/internal/rpc/rpc_bench_test.go` creates test data via raw SQL INSERT instead of using Phase 02 factory functions.

**Evidence:**
- Line 127-130 in rpc_bench_test.go: Direct SQL INSERT statements
- Phase 02 provides: `NewTestPlayer()`, `NewTestGear()`, `NewTestMatch()`, builder pattern

**Impact:** Code duplication, inconsistent test data, lost opportunity for reuse

**Recommendation:** Refactor benchmarks to use `NewTestPlayer()` and builder pattern

### 2. Phase 04 Load Tests Don't Use Phase 02 Testcontainers

**Issue:** k6 load tests (`concurrent_players.js`, `mixed_workload_enhanced.js`) require manual backend startup instead of using automated database provisioning.

**Evidence:**
- Load tests connect to `http://localhost:7350` (assumes backend is running)
- Phase 02 provides `testhelpers.SetupTestDB()` for automated PostgreSQL containers

**Impact:** Operational burden, cannot run load tests in isolation

**Recommendation:** Integrate testcontainers or Docker Compose for automated load test execution

### 3. No Unified Test Runner (FND-03)

**Issue:** Cannot run all tests with a single command.

**Evidence:**
- `make backend-test-go` runs Go tests
- `godot4 --headless --script test/run_all_tests.gd` runs Godot tests
- No unified script exists

**Impact:** Developer friction, no unified test report

**Recommendation:** Create `./scripts/test-all.sh` that runs both test suites and aggregates results
