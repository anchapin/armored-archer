# Roadmap: v3.4.0 Tactical Gameplay & PvE Campaign

## Core Value

**Players can fight enemies, earn loot, and progress through a campaign — with working PvP matchmaking and combat synchronization via Nakama backend.**

This milestone bridges the gap between polished UI (shipped v3.0.0–v3.3.0) and actual gameplay loops. Both PvP and PvE paths become fully playable end-to-end.

## Context

**What's Done:**
- v3.3.0: Particle effects, post-processing, UI polish (shipped 2026-03-27)
- v3.2.0: 239 pixel art sprite assets (shipped 2026-03-26)
- Core autoload managers exist: `CombatSyncManager.gd` (185 lines), `MatchmakingManager.gd` (171), `InventoryManager.gd` (218)
- Backend modules exist: `combat_system.ts` (1044 lines), `matchmaker.ts` (998), `gear_system.ts` (1850)
- UI scenes exist: `combat_menu.gd` (260), `matchmaking_menu.gd` (296), `gear_inventory.gd` (289), `loadout.gd` (239), `campaign_map.gd` (236)
- Backend test coverage: 94.55% lines, 0 TypeScript errors

**What's Missing:**
- Scenes are not wired to managers (static placeholders)
- No PvE system (CampaignManager, EnemyAIManager, LootManager don't exist)
- No loot generation or campaign progression
- No integration tests for gameplay loops

**Why This Matters:**
v4.0.0 (Alpha Readiness) requires a playable game loop. Without v3.4.0 delivering functional gameplay, load testing and security audits have nothing to validate against.

## Phase Details

### Phase 01: PvP Backend Integration
**Goal:** Players can create/join matches, fight opponents with real-time sync, and manage gear loadouts via Nakama backend.

**Depends on:** Nothing (first phase — existing managers and backend modules are the foundation)

**Requirements:** PVP-01, PVP-02, PVP-03, PVP-04, PVP-05, PVP-06, PVP-07

**Success Criteria** (what must be TRUE):
1. Player opens matchmaking menu → sees list of available matches with rank/filter options
2. Player creates a match → other players see it in the match list
3. Player joins a match → transitions to combat screen with opponent data loaded
4. Player aims and shoots → opponent sees the move within 1 second; health bars update
5. Combat ends → win/loss is determined server-side; results display correctly
6. Player opens gear inventory → sees owned gear loaded from backend
7. Player equips gear → stats update and loadout persists on relog

**Plans:** TBD (2-3 plans expected)

### Phase 02: Campaign Map & Encounter System
**Goal:** Players can navigate a campaign map, select encounters, and transition to combat with enemies.

**Depends on:** Phase 01 (needs combat infrastructure working)

**Requirements:** PVE-01, PVE-02, PVE-03, PVE-04

**Success Criteria** (what must be TRUE):
1. Player opens campaign map → sees 8 encounters across 3 difficulty tiers (Forest → Cavern → Mountain)
2. Locked encounters show as unavailable until prerequisite difficulty is cleared
3. Player clicks an encounter → transitions to combat with correct enemy stats loaded
4. Campaign progress saves on victory → completed encounters persist across sessions

### Phase 03: Enemy AI & PvE Combat
**Goal:** Enemies take turns, use tactics based on difficulty, and combat plays out fully in PvE mode.

**Depends on:** Phase 02 (needs encounters spawning enemies)

**Requirements:** PVE-05, PVE-06, PVE-07

**Success Criteria** (what must be TRUE):
1. After player takes a turn → enemy takes a turn automatically (no manual input needed)
2. Difficulty 1 enemies use random attacks; Difficulty 3 enemies adapt to player health/defense
3. Combat log displays both player and enemy moves with damage values
4. Combat resolves in 3-5 turns on average (feels fast, not grindy)

**Plans:** 1/1 Complete (phase-03-SUMMARY.md)

---

### Phase 04: Loot System & Progression
**Goal:** Victory grants loot (gear + XP + gold), inventory updates, and campaign progression unlocks.

**Depends on:** Phase 03 (needs PvE combat to complete)

**Requirements:** PVE-08, PVE-09, PVE-10, PVE-11

**Success Criteria** (what must be TRUE):
1. Player wins a combat → loot screen shows rewards (gear + XP + gold)
2. Loot rarity scales with difficulty (Common → Rare → Legendary)
3. Looted gear appears in inventory immediately; player can equip it
4. XP accumulates → player level increases; difficulty tiers unlock based on progress
5. Full campaign run (8 encounters) completes without crashes

**Plans:** 1/1 Complete (phase-04-SUMMARY.md)

---

### Phase 05: Campaign State Persistence
**Goal:** Campaign progress syncs with server and persists across sessions and devices.

**Depends on:** Phase 04 (needs loot and stage completion working)

**Requirements:** PERSIST-01, PERSIST-02, PERSIST-03, PERSIST-04

**Success Criteria** (what must be TRUE):
1. Client sends valid difficulty enum to stage_complete RPC (not hardcoded "normal")
2. Server has `get_campaign_progress` RPC that returns completed and unlocked stages
3. Client fetches campaign progress from server on connection and merges with local state
4. Campaign progress persists after closing and reopening the game

**Plans:** 3 plans

Plans:
- [ ] 05-01-PLAN.md — Backend: fix difficulty validation, add get_campaign_progress RPC
- [ ] 05-02-PLAN.md — Client: sync_campaign_progress, difficulty fix, connection handler
- [ ] 05-03-PLAN.md — Human verification checkpoint for e2e persistence
