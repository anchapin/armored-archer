# Requirements: Armored Archer

**Defined:** 2026-03-22
**Core Value:** Players can enjoy a polished, responsive archery game with reliable performance and minimal bugs.

## v2.5.0 Requirements

Requirements for advanced testing frameworks milestone. Each maps to roadmap phases.

### Godot Coverage Tools

- [x] **GODOT-01**: Evaluate existing open-source tools for Godot 4 line coverage instrumentation
- [x] **GODOT-02**: Select appropriate coverage tool or confirm custom solution required
- [ ] **GODOT-03**: Integrate selected coverage solution with existing GUT 9.6.0 framework
- [ ] **GODOT-04**: Generate HTML coverage reports for Godot autoload tests
- [ ] **GODOT-05**: Extend coverage dashboard to show Godot line coverage (replacing pass rate proxy)

### Mutation Testing

- [x] **MUT-01**: Install and configure go-mutesting for mutation testing
- [x] **MUT-02**: Create custom execution script to handle MUTATE_ORIGINAL/MUTATE_CHANGED environment variables
- [x] **MUT-03**: Integrate mutation testing with existing testify and testcontainers infrastructure
- [x] **MUT-04**: Configure package-specific mutation score thresholds (combat: 85%, matchmaking: 80%, others: 75%)
- [x] **MUT-05**: Create nightly GitHub Actions workflow for mutation testing (not on every PR)
- [x] **MUT-06**: Display mutation score on coverage dashboard with trend tracking
- [x] **MUT-07**: Respect flaky test quarantine build tags during mutation testing

### Property-Based Testing

- [x] **PBT-01**: Add invariant tests for progression system (XP consistency, level-up mechanics)
- [x] **PBT-02**: Add invariant tests for matchmaking system (skill matching fairness, algorithm properties)
- [x] **PBT-03**: Add invariant tests for inventory system (item constraints, validation rules)
- [x] **PBT-04**: Use testing/quick for simple invariants across progression, matchmaking, inventory
- [x] **PBT-05**: Evaluate rapid library for complex state machine testing (matchmaking state transitions)
- [x] **PBT-06**: Add 20+ property tests total across 3 systems (progression, matchmaking, inventory)

### Go Coverage to 60%

- [x] **COV-01**: Increase Go coverage from 34.5% to 60% across all 27 packages
- [x] **COV-02**: Implement incremental threshold gates (45% → 52.5% → 60%)
- [x] **COV-03**: Increase progression package coverage from 50% to 75%
- [x] **COV-04**: Increase matchmaking package coverage from 65% to 80%
- [x] **COV-05**: Increase store, season, notifications packages coverage from 30-35% to 50-55%
- [x] **COV-06**: Automate gap analysis to identify zero-coverage functions
- [ ] **COV-07**: Leverage existing factory fixtures and testcontainers for new tests
- [x] **COV-08**: Enforce overall 60% coverage threshold in CI/CD

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Full Godot line coverage across entire codebase | Research phase only - evaluate tools before building custom solution |
| Mutation testing on every PR commit | Performance concern - nightly execution only |
| Property-based testing for store, seasons, notifications | Deferred to v2.6.0 after progression/matchmaking/inventory proven |
| Commercial testing tools | Open-source solutions (go-mutesting, testing/quick, rapid) are sufficient |
| Godot AST parser for all GDScript features | Initial pilot focused on autoload scripts only |
