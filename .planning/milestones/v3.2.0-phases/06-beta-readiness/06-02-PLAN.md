# Plan 06-02: Fix Nakama Beta Container Configuration

**Objective**: Fix the hardcoded database connection string in docker-compose.beta.yml to use environment variables from .env.beta, enabling Nakama beta container to start successfully

**Purpose**: Resolve critical configuration bug preventing beta deployment from running

**Output**: Working Nakama beta container with all services healthy

## Context

@.planning/phases/06-beta-readiness/06-VERIFICATION.md
@.planning/phases/06-beta-readiness/06-01-PLAN.md
@backend/docker-compose.beta.yml
@backend/.env.beta

## Background

The VERIFICATION.md identified a critical gap: the Nakama beta container is in a restart loop due to a configuration mismatch in docker-compose.beta.yml. The entrypoint currently hardcodes the database connection string instead of using the `${DATABASE_ADDRESS}` environment variable from .env.beta.

**Current Issue:**
- Lines 55-56 in docker-compose.beta.yml have a fallback value that may not match .env.beta
- The base docker-compose.yml file defines nakama service with entrypoint using `changeme` password
- Docker Compose merge behavior may not be properly overriding the entrypoint

**Impact:**
- Beta deployment NOT successful (must-have #1 failed)
- Cannot onboard beta users, measure error rate, run load tests, collect bug reports, or get stakeholder approval
