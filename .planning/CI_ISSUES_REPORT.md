## Issues Found and Fixed

### 1. Schema Validation Test Discovery Failure ❌ → ✅ FIXED

**Problem:** The `schema-validation` job failed because Jest couldn't find the test file at `tests/integration/schema.test.ts`.

**Root Cause:** In `backend/jest.integration.config.js`, the `roots` was set to only `['<rootDir>/src']`, which excluded the `tests/` directory.

**Fix Applied:**
```javascript
// Before:
roots: ['<rootDir>/src'],

// After:
roots: ['<rootDir>/src', '<rootDir>/tests'],
```

**File Modified:** `backend/jest.integration.config.js`

**Verification:** Re-running `act -W .github/workflows/ci.yml -j schema-validation` now passes all 28 tests.

### 3. SonarCloud Docker Port Conflict

**Problem:** The SonarCloud job fails with:
```
Error: failed to start container: Error response from daemon: failed to set up container networking: driver failed programming external connectivity on endpoint act-CI-SonarCloud-Code-Quality-dbc8538c4b01470462686a16ff6585ad-2a9fe5d736e678f467c081fb038ce5c2483c2c22cfcc91d0688bf4e096d518c6: Bind for 0.0.0.0:7350 failed: port is already allocated
```

**Root Cause:** The SonarCloud job uses the same service configuration as `backend-test` (Nakama on port 7350), causing a port conflict when act tries to set up network isolation.

**Status:** Not a blocking issue - this only happens when running `act` locally. In production GitHub Actions, each job runs in its own isolated runner with its own network.

**Recommendation:** No fix needed for production CI. For local testing with `act`, run jobs individually rather than in parallel to avoid conflicts.
