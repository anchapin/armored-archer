**Phase**: 1.2

---

## 🎯 Goal

Execute database migrations on the alpha environment and verify data integrity.

---

## 📋 Tasks

### Task 1.2.1: Migration Preparation

**What**: Prepare for migration execution

- [ ] Review all migration scripts in `backend/data/*.sql`
- [ ] Verify migration order and dependencies
- [ ] Test migrations on staging/dev environment
- [ ] Create pre-migration database backup
- [ ] Document rollback procedure for each migration
- [ ] Schedule migration window (if downtime required)

**Verification**: Migration plan reviewed and tested

---

### Task 1.2.2: Pre-Migration Backup

**What**: Create full database backup before migrations

- [ ] Take database snapshot
- [ ] Verify backup integrity
- [ ] Store backup in secure location
- [ ] Document backup location and restore procedure
- [ ] Test restore procedure (optional but recommended)

**Verification**: Backup completed and verified

---

### Task 1.2.3: Execute Migrations

**What**: Run all database migrations

```bash
# Using Docker Compose
docker exec -it armored_archer_nakama /nakama/nakama migrate up

# Or directly with psql
psql -h alpha-db -U postgres -d nakama -f backend/data/001_initial_schema.sql
psql -h alpha-db -U postgres -d nakama -f backend/data/002_player_stats.sql
# ... continue for all migrations
```

- [ ] Execute migrations in order
- [ ] Monitor for errors
- [ ] Log all migration output
- [ ] Verify each migration completes successfully

**Verification**: All migrations complete without errors

---

### Task 1.2.4: Migration Verification

**What**: Verify migrations applied correctly

- [ ] Check migration version: `SELECT * FROM migration_version;`
- [ ] Verify all tables exist: `\dt` in psql
- [ ] Check table structures: `\d table_name` for each table
- [ ] Verify indexes created: `\di` in psql
- [ ] Check constraints: `\d+ table_name` for constraints
- [ ] Verify enum types: `\dT` in psql

**Verification**: Database schema matches expected state

---

### Task 1.2.5: Data Integrity Checks

**What**: Verify data integrity post-migration

- [ ] Check row counts match expected values
- [ ] Verify foreign key relationships
- [ ] Check for NULL values in NOT NULL columns
- [ ] Verify default values applied correctly
- [ ] Check data types match schema
- [ ] Run data validation queries

**Verification**: Data integrity validated

---

### Task 1.2.6: Performance Optimization

**What**: Optimize database performance

- [ ] Run ANALYZE on all tables
- [ ] Check query planner statistics
- [ ] Verify index usage with EXPLAIN ANALYZE
- [ ] Configure connection pooling settings
- [ ] Set up query logging (slow query log)
- [ ] Configure vacuum settings (PostgreSQL)

**Verification**: Database optimized for alpha load

---

## ✅ Success Criteria

- [ ] All migrations executed successfully

- [ ] Data integrity verified
- [ ] Performance optimizations applied
- [ ] Backup and rollback procedures documented

## 🛑 Checkpoint

**Type**: `checkpoint:human-verify`

**What to Verify**:
- Database migrations completed successfully
- Data integrity maintained
- Performance is acceptable

**How to Verify**:
1. Connect to alpha database: `psql -h alpha-db -U postgres -d nakama`
2. Check tables: `\dt` (should show all expected tables)
3. Check migration version: `SELECT * FROM migration_version;`
4. Run test queries to verify data accessible
5. Check query performance with EXPLAIN ANALYZE

**Resume Signal**: "Database migrations verified, proceed to Go module deployment"
