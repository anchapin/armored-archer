# Phase 1.3-PLAN: Go Module Deployment

**Milestone**: v2.1.0 - Alpha Launch & Stabilization  
**Phase**: 1.3  
**Duration**: 1 day  
**Priority**: Critical

---

## 🎯 Goal

Deploy the Go backend module to the alpha Nakama server and verify it loads correctly.

---

## 📋 Tasks

### Task 1.3.1: Build Go Module for Production

**What**: Compile Go module with production settings

```bash
cd backend

# Build with production optimizations
go build -o build/server -ldflags="-s -w" ./cmd/server

# Verify build
ls -lh build/server
file build/server
```

- [ ] Build Go module with production flags
- [ ] Verify binary created successfully
- [ ] Check binary size (should be ~9-10MB)
- [ ] Run binary tests: `./build/server --test` (if applicable)

**Verification**: Production binary built successfully

---

### Task 1.3.2: Transfer to Alpha Server

**What**: Deploy binary to alpha environment

```bash
# Using SCP
scp build/server user@alpha-server:/opt/nakama/modules/

# Or using deployment pipeline
./scripts/deploy-alpha.sh

# Or using Docker
docker build -t armored-archer:alpha .
docker push registry/armored-archer:alpha
```

- [ ] Transfer binary to alpha server
- [ ] Set correct permissions: `chmod 755 /opt/nakama/modules/server`
- [ ] Set correct ownership: `chown nakama:nakama /opt/nakama/modules/server`
- [ ] Verify file integrity (checksum comparison)

**Verification**: Binary deployed to alpha server

---

### Task 1.3.3: Update Nakama Configuration

**What**: Configure Nakama to load Go module

```yaml
# nakama/config.yml
runtime:
  vm:
    js:
      enabled: false  # Disable JS if migrating fully to Go
    go:
      enabled: true
      entrypoint: InitModule
      paths:
        - /opt/nakama/modules/server
```

- [ ] Update Nakama config for Go module
- [ ] Set module entry point: `InitModule`
- [ ] Configure module paths
- [ ] Disable TypeScript/JS modules (if applicable)
- [ ] Review other runtime settings

**Verification**: Nakama configuration updated

---

### Task 1.3.4: Pre-Deployment Checks

**What**: Verify everything is ready for deployment

- [ ] Check Nakama version compatibility
- [ ] Verify Go module dependencies
- [ ] Check environment variables loaded
- [ ] Verify database connection string
- [ ] Check network connectivity to dependencies
- [ ] Review Nakama logs for any pre-existing errors

**Verification**: All pre-deployment checks passed

### Task 1.3.5: Deploy Go Module

**What**: Start Nakama with Go module

```bash
# If using systemd
sudo systemctl restart nakama

# If using Docker
docker-compose up -d nakama

# Monitor startup
sudo journalctl -u nakama -f
# Or
docker-compose logs -f nakama
```

- [ ] Restart Nakama service
- [ ] Monitor startup logs
- [ ] Check for module load errors
- [ ] Verify Go module initialized
- [ ] Check for any panic or fatal errors

**Verification**: Nakama started successfully with Go module

---

### Task 1.3.6: Module Load Verification

**What**: Verify Go module loaded correctly

```bash
# Check Nakama logs for module initialization
grep "InitModule" /var/log/nakama/nakama.log

# Should see something like:
# "InitModule completed successfully"
# "Registered RPC handler: player_stats"
# "Registered RPC handler: combat_action"
# etc.
```

- [ ] Check logs for successful module initialization
- [ ] Verify all RPC handlers registered
- [ ] Verify all matchmakers registered
- [ ] Verify all hooks registered
- [ ] Check for any warnings or errors

**Verification**: Go module loaded without errors

## 🛑 Checkpoint

**Type**: `checkpoint:human-verify`

**What to Verify**:
- Go module loaded successfully in Nakama
- All RPC handlers registered
- No errors in startup logs

**How to Verify**:
1. Check Nakama logs: `journalctl -u nakama -n 100` or `docker logs nakama`
2. Look for "InitModule completed successfully"
3. Verify RPC handlers listed in logs
4. Test health endpoint: `curl http://localhost:7350/health`
5. Test a simple API call

**Resume Signal**: "Go module verified, proceed to smoke testing"
