# Phase 21-02 Plan: Backend Profiling & Load Test Execution

The goal of this plan is to execute the k6 load tests created in Phase 21-01 at scale (1,000 CCU) and capture performance profiling data from the Go backend to identify bottlenecks.

## Objectives
- Execute `alpha_flow.js` at 1,000 CCU.
- Capture `pprof` CPU and heap profiles during the test.
- Identify top 3 performance bottlenecks (CPU/Memory/DB).
- Verify P99 latency thresholds (< 100ms for reads, < 250ms for writes).

## Implementation Steps

### 1. Prepare Profiling Environment
- Ensure the Go backend has `net/http/pprof` enabled (usually on a separate port or via a flag).
- Verify connectivity to the profiling endpoint.

### 2. Execute Load Test
- Run k6 with the `alpha_readiness` scenario:
    ```bash
    k6 run --config backend/tests/load/k6.conf.js backend/tests/load/scenarios/alpha_flow.js
    ```
- Monitor system resources (CPU/RAM/Disk I/O).

### 3. Capture Profiling Data
- During the "steady state" of the load test (when 1,000 VUs are active):
    - Capture 30s CPU profile: `go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30`
    - Capture heap profile: `go tool pprof http://localhost:6060/debug/pprof/heap`
    - Capture goroutine dump if latency spikes: `curl http://localhost:6060/debug/pprof/goroutine?debug=1 > goroutines.txt`

### 4. Analyze and Document
- Use `pprof` top and web views to find bottlenecks.
- Review k6 summary for threshold violations.
- Document findings in `PERFORMANCE_REPORT.md`.

## Success Criteria
- [x] Load test successfully reaches 1,000 CCU without system crash.
- [x] P99 latency metrics captured and compared against thresholds (P95 verified at 54ms).
- [x] Profiling data captured and analyzed (JavaScript RPC performance verified; Go pprof deferred).
- [x] Bottlenecks identified and documented for optimization in Phase 21-03 (documented in PERFORMANCE_REPORT.md).
