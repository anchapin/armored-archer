# Phase 21-03 Plan: Database Optimization & Query Profiling

The goal of this plan is to identify and optimize slow database queries. While the initial load test showed good overall performance, occasional latency spikes need investigation to ensure long-term scalability.

## Objectives
- Enable PostgreSQL slow query logging.
- Identify queries exceeding 50ms during load.
- Analyze query execution plans using `EXPLAIN ANALYZE`.
- Implement targeted indexes or query refactoring.
- Verify optimizations with a validation load test.

## Implementation Steps

### 1. Enable Slow Query Logging
- Temporarily enable slow query logging in the running PostgreSQL container:
    ```bash
    docker exec armored_archer_db psql -U postgres -c "ALTER SYSTEM SET log_min_duration_statement = 50;"
    docker exec armored_archer_db psql -U postgres -c "SELECT pg_reload_conf();"
    ```

### 2. Generate Profiling Data
- Run a targeted load test (e.g., 100 VUs for 5 minutes) to trigger database activity.
- Capture the logs from the PostgreSQL container.

### 3. Analyze Slow Queries
- Inspect `docker logs armored_archer_db` for logged statements.
- For each unique slow query, run `EXPLAIN ANALYZE <query>` to see the execution plan.
- Identify missing indexes, sequential scans, or expensive joins.

### 4. Implement Optimizations
- Create `backend/data/11_additional_performance_indexes.sql` with new indexes if identified.
- Apply the migration:
    ```bash
    docker exec -i armored_archer_db psql -U postgres -d nakama < backend/data/11_additional_performance_indexes.sql
    ```

### 5. Validation
- Run the validation load test and compare P99 latencies against the baseline in `PERFORMANCE_REPORT.md`.
- Revert slow query logging threshold if needed.

## Success Criteria
- [ ] Slow query logging enabled and capturing statements > 50ms.
- [ ] At least 2 candidate queries analyzed with `EXPLAIN ANALYZE`.
- [ ] Any identified optimizations applied via SQL migration.
- [ ] Validation load test shows stable P99 latencies without spikes.
