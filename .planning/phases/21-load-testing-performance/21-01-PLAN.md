# Phase 21-01 Plan: Alpha Readiness Load Test Implementation

The goal of this plan is to scale the existing load testing infrastructure to 1,000 CCU and implement a realistic "Alpha Flow" scenario that simulates a complete player session.

## Objectives
- Implement `alpha_flow.js` scenario: Login -> Get Stats -> Matchmake -> Simulate Combat -> Store.
- Update `k6.conf.js` to support 1,000 concurrent users.
- Configure P99 latency thresholds for Alpha readiness (< 100ms for critical RPCs).

## Implementation Steps

### 1. Create Alpha Flow Scenario
- Create `backend/tests/load/scenarios/alpha_flow.js`:
    - Simulate a sequence of RPC calls: `get_player_stats`, `get_leaderboard`, `join_matchmaking`, `combat_action` (simulated), `submit_combat_results`, `get_inventory`.
    - Use random "think time" between actions.

### 2. Update k6 Configuration
- Modify `backend/tests/load/k6.conf.js`:
    - Add `alpha_readiness` scenario with 1,000 VUs target.
    - Update stages for gradual ramp-up to 1,000 users.
    - Set strict P99 thresholds (< 100ms for reads, < 250ms for writes).

### 3. Verification
- Run a small-scale test (10-50 VUs) to verify the `alpha_flow` logic.
- `make backend-load-test` (manually triggered for full scale).

## Success Criteria
- [x] `alpha_flow.js` correctly simulates the full player lifecycle.
- [x] `k6.conf.js` is configured for 1,000 VUs.
- [x] Thresholds reflect Alpha readiness requirements.
