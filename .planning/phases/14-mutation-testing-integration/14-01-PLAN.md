  </files>
  <read_first>
    - data/flaky-test-quarantine.json
  </read_first>
  <action>
    Create scripts/mutation-exec-handler.sh with:

    1. Shebang and error handling: `#!/bin/bash set -e`

    2. Environment variable handling (provided by go-mutesting):
       - MUTATE_ORIGINAL: Original source file path
       - MUTATE_CHANGED: Mutated source file path
       - MUTATE_PACKAGE: Package import path
       - MUTATE_TIMEOUT: Timeout for this mutation (default to 30s if empty)

    3. Input validation:
       - Check if MUTATE_ORIGINAL and MUTATE_CHANGED are set
       - Exit with error if not set (helps with debugging)

    4. Mutation setup:
       - Replace original file with mutated: `cp "$MUTATE_CHANGED" "$MUTATE_ORIGINAL"`
       - Change to package directory: `cd "$(dirname "$MUTATE_ORIGINAL")"`

    5. Test infrastructure integration:
       - Export testcontainers environment variables:
         - TESTDB_HOST=localhost
         - TESTDB_PORT=5432
       - Quarantine handling: Check if data/flaky-test-quarantine.json exists and has entries
         - If quarantine exists, build skip list from JSON keys
         - Use `-run` flag to skip quarantined tests

    6. Test execution:
       - Run: `go test -v -timeout="${MUTATE_TIMEOUT:-30s}" -run='^((?!Quarantined).)*$' .`
       - The regex pattern skips tests with "Quarantined" in name

    7. Mutation result determination:
       - If tests PASS (exit 0): mutation was killed (good)
         - Exit 0 to indicate mutation detected
       - If tests FAIL (exit non-zero): mutation survived (bad)
         - Exit 1 to indicate mutation not detected

    8. Cleanup: Restore original file if needed (go-mutesting manages this, but add safety comment)

    9. Make executable: `chmod +x scripts/mutation-exec-handler.sh`

    Note: The quarantine system uses data/flaky-test-quarantine.json with format `{"testName": {"reason": "..."}}`. We skip tests that are in this file.
  </action>

  </verify>
