# Phase 19-01 Plan: Analytics Unit Testing

The goal of this plan is to achieve high coverage for the `internal/analytics` package by implementing comprehensive unit tests for both base and alpha-specific events.

## Objectives
- Achieve **80%+ coverage** in the `internal/analytics` package.
- Verify correct mapping of event properties to Nakama logs.
- Ensure all helper functions correctly generate and log events.

## Implementation Steps

### 1. Setup Base Analytics Tests
- Create `backend/internal/analytics/analytics_test.go`.
- Implement a `CaptureLogger` that stores logged messages for verification.
- Test `LogEvent` (base logic).
- Test all standard event loggers:
    - `LogSessionStart`, `LogSessionEnd`
    - `LogPurchase` (success/fail)
    - `LogLevelUp`, `LogGearObtained`
    - `LogRPCError`, `LogRPCLatency`
    - `LogCustomEvent`
    - `LogFirstSession`, `LogDailyLogin`

### 2. Setup Alpha Event Tests
- Create `backend/internal/analytics/alpha_events_test.go`.
- Use table-driven tests to cover representative events from each category:
    - User Lifecycle (Registration, Onboarding)
    - Engagement (Session, Retention)
    - Feature Usage (Combat, Gear, Matchmaking)
    - Store (Purchase, Currency)
    - Progression (Level Up, XP, Quests)
- Verify `ToMap` logic for `AlphaEventProperties`.

## Testing Strategy
- **Unit Tests**: Mock `runtime.Logger` to intercept `Debug` calls and verify:
    - `event_name` matches.
    - `user_id` matches.
    - `properties` contain expected keys and values.
- **Coverage**: Run `go test -coverprofile=coverage.out ./internal/analytics/...` to verify results.

## Success Criteria
- [ ] `internal/analytics` package coverage reaches **80%+**.
- [ ] At least 20 unique test cases covering various analytics flows.
- [ ] All tests pass without external dependencies.
