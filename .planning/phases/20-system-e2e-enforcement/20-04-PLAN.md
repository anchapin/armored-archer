## Gap Analysis

The VERIFICATION.md identified two gaps blocking E2E test infrastructure:

1. **Circular dependency in logger.js**: The `config.logger.format` is accessed during module initialization in `logger.js` (lines 23-26, 157), but config may not be fully loaded yet
2. **TestNakamaClient methods are TODO stubs**: The E2E test helper returns empty values instead of actual HTTP calls

## Implementation Plan

### Task 1: Fix Circular Dependency in Logger.js

**Problem**: In `backend/data/modules/config/logger.js`, both `initializeLogScrubber()` and `getFormat()` access `config.logger.*` at module load time, causing circular dependency when bundled modules initialize.

**Solution**: Make config access lazy by checking if config exists before accessing properties, or defer the logger initialization until first use.

**Action**: Modify `logger.js`:
1. Change `getFormat()` to check if `config` and `config.logger` exist, defaulting to 'json' if not
2. Change `initializeLogScrubber()` to return a no-op scrubber if config not ready
3. Change transport creation to handle missing config gracefully

### Task 2: Implement TestNakamaClient Methods

**Problem**: `TestNakamaClient` methods (`AuthenticateDevice`, `RPC`) return empty values.

**Solution**: Implement actual HTTP client logic using Go's `net/http` to call Nakama REST API.

**Action**: Modify `backend/tests/e2e/match_flow_test.go`:
1. Implement `AuthenticateDevice` to POST to `/v2/account/authenticate/device` with device ID
2. Implement `RPC` to POST to `/v2/rpc/{id}` with auth token
3. Remove `t.Skip()` from test cases to enable actual execution
4. Add proper error handling and response parsing

### Task 3: Enable E2E Tests

**Action**: Update test file to remove skip guards and run actual tests once infrastructure is ready.
