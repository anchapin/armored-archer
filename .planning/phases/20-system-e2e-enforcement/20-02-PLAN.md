# Phase 20-02 Plan: System E2E Match Flow

The goal of this plan is to implement a high-level E2E test that verifies the core "Join Queue -> Play Match -> Complete" flow using real Nakama and Database containers.

## Objectives
- Implement first E2E test in `backend/tests/e2e`.
- Verify Nakama server integration with custom Go modules.
- Ensure end-to-end correctness of the primary gameplay loop.

## Implementation Steps

### 1. Setup E2E Test Suite
- Create `backend/tests/e2e/match_flow_test.go`.
- Use `testhelpers.SetupTestDB` to start PostgreSQL.
- Use `testhelpers.SetupNakamaServer` to start Nakama.
- Implement a `NakamaClient` helper for easier RPC calling from tests.

### 2. Implement Match Flow Test
- **Authentication**: Authenticate two test users via device ID.
- **Matchmaking**: Both users join the matchmaking queue.
- **Match Discovery**: Verify both users receive a match ID.
- **Match Play**: Simulate combat actions via RPC.
- **Completion**: Submit match completion and verify results.
- **Persistence**: Verify stats (XP, Rank) are updated in the database.

## Testing Strategy
- Use `testcontainers-go` for zero-setup execution.
- Focus on the "Happy Path" to minimize brittleness.
- Use longer timeouts (60s) for container startup.

## Success Criteria
- [ ] `TestCompleteMatchFlowE2E` passes consistently.
- [ ] Database verification confirms data persistence after match.
- [ ] Nakama logs show successful RPC execution.
