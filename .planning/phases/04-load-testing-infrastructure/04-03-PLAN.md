## Tasks

### Task 1: Create concurrent_players.js scenario for 100+ user validation

**Files:** `backend/tests/load/scenarios/concurrent_players.js` (NEW)

**Read First:**
- `backend/tests/load/scenarios/player_stats.js` - Read existing authentication and RPC call patterns
- `backend/tests/load/scenarios/mixed_workload.js` - Read helper function patterns

**Action:**
Create `concurrent_players.js` with staged ramp-up to 150 concurrent users (exceeding 100 requirement).

Implement:

1. **Stages configuration** - 5 stages for gradual ramp-up and sustained load:
   - 2m ramp-up to 50 users
   - 3m ramp-up to 100 users (PERF-03 requirement)
   - 5m sustained at 150 users (exceeds requirement)
   - 2m ramp-down to 50 users
   - 1m ramp-down to 0

2. **Thresholds** - Enforce performance SLOs:
   - Error rate < 1% (errors: ['rate<0.01'])
   - P95 latency < 200ms (http_req_duration: ['p(95)<200'])
   - P99 latency < 500ms (http_req_duration: ['p(99)<500'])

3. **Traffic pattern** - 70% get_player_stats, 20% get_leaderboard, 10% submit_feedback
   - Use Math.random() for weighted distribution
   - Call appropriate RPC based on random value

4. **Metrics** - Track per-RPC latency:
   - const statsLatency = new Trend('get_player_stats_latency')
   - const leaderboardLatency = new Trend('get_leaderboard_latency')
   - const feedbackLatency = new Trend('submit_feedback_latency')

5. **Authentication** - Use authenticate helper from existing scenarios

6. **Sleep** - Add 1-2 second sleep between requests to simulate realistic think time

**Verify:**
```bash
cd backend/tests/load && k6 run scenarios/concurrent_players.js --duration 30s --vus 50
```

Expected: Test runs for 30 seconds, 50 VUs complete successfully, thresholds pass.

**Done:**
concurrent_players.js exists with staged ramp-up to 150 users, thresholds enforced, per-RPC metrics tracked.
